## 2. User Flow Diagrams

### Visitor Flow
```
Homepage → Browse Properties/Requests/Agents → View Detail → Contact/Register
                       ↓
                  Interactive Map
                       ↓
              View Property/Request on Map
```

### Registered User Flow
```
Register/Login → Dashboard → Post Property/Request → Wait for Approval
       ↓              ↓              ↓
   Browse       View Own Content ← Edit/Delete
   Content      
       ↓
Create Agent Profile (optional)
       ↓
Receive Notifications on Matches
```

### Agent Flow
```
Create Agent Profile → Link Properties to Requests → Buyer Confirms
        ↓                      ↓                         ↓
   View Matches ← Triangle Connected ← Notification Sent
        ↓
   Contact via WhatsApp
```

### Service Provider Flow
```
Register as Provider → Admin Approval → Public Profile
        ↓                      ↓              ↓
   Edit Profile       Wait for Approval    Receive Inquiries
```

### Admin Flow
```
Admin Dashboard → Moderate Content (Properties/Requests/Providers)
       ↓
   Manage Users (Suspend/Activate)
       ↓
   View Analytics & Export Data
```

## 3. Modern Design UI/UX Considerations

### Design System
- **Framework**: Tailwind CSS 4 with shadcn/ui components
- **Color Palette**:
  - Primary: Deep Blue (#1e40af) - Trust, professionalism
  - Secondary: Emerald (#10b981) - Success, growth
  - Accent: Orange (#f97316) - Calls-to-action
  - Neutral: Slate palette for text and backgrounds
  - Dark mode support via next-themes

### Typography
- **Font Family**: Inter (system-ui fallback)
- **Hierarchy**:
  - H1: 2.5rem (40px) - Page titles
  - H2: 1.875rem (30px) - Section headers
  - H3: 1.5rem (24px) - Card titles
  - Body: 1rem (16px) - Base text
  - Small: 0.875rem (14px) - Metadata, captions

### Layout Principles
- **Mobile-First**: All designs start at 320px viewport
- **Container**: Max-width 1280px (xl), 1024px (lg), centered
- **Spacing Scale**: 4px base unit (4, 8, 12, 16, 24, 32, 48, 64)
- **Grid System**: 12-column responsive grid
- **Border Radius**: 
  - Small: 6px (buttons, inputs)
  - Medium: 12px (cards)
  - Large: 16px (modals, containers)
  - Full: 9999px (pills, avatars)

### Component Standards

#### Cards
- Background: white (dark: gray-800)
- Border: 1px solid gray-200
- Shadow: shadow-sm (hover: shadow-md transition)
- Padding: 24px (p-6)
- Border radius: 12px (rounded-xl)

#### Buttons
- Primary: bg-blue-600 hover:bg-blue-700 text-white
- Secondary: bg-gray-100 hover:bg-gray-200 text-gray-900
- Outline: border-gray-300 hover:bg-gray-50
- Ghost: hover:bg-gray-100 (for icon buttons)
- Sizes: sm (32px), md (40px), lg (48px height)
- Border radius: 8px (rounded-lg)
- Font: medium weight, 0.875rem

#### Forms
- Input height: 40px
- Border: 1px solid gray-300, focus:border-blue-500
- Background: white
- Padding: 10px 12px
- Border radius: 8px
- Error state: border-red-500, text-red-600
- Label: text-sm font-medium text-gray-700

#### Navigation
- Header: Fixed top, height 64px, blur backdrop
- Mobile: Hamburger menu with slide-in drawer
- Active state: text-blue-600 font-medium
- Breadcrumbs: For nested pages

### Key UI Features

#### Homepage Sections
1. **Hero**: Full-width with search bar, gradient overlay
2. **Stats Bar**: Platform statistics (properties, agents, requests)
3. **Featured Properties**: 4-card grid, horizontal scroll on mobile
4. **Recent Requests**: List view with budget display
5. **Top Agents**: Avatar cards with rating
6. **Services**: Icon grid for quick navigation
7. **Map Preview**: Embedded mini-map with cluster pins

#### Property Detail Page
- Image gallery with thumbnail navigation
- Price badge prominently displayed
- Map with property location pin
- Agent/Owner card with contact CTA
- Similar properties section
- Share and save buttons

#### Interactive Map
- Full-screen toggle option
- Pin clustering for dense areas
- Filter sidebar (price, type, status)
- Price heatmap layer (optional)
- Click pin → summary card popup
- "View in list" toggle

#### Dashboard
- Sidebar navigation (collapsible on mobile)
- Stats cards at top
- Tabbed content areas
- Empty states with illustration
- Loading skeletons for async content

### Animations & Interactions
- **Page Transitions**: Fade-in with 200ms ease-out
- **Hover States**: Scale 1.02 on cards, shadow elevation
- **Button Clicks**: Active scale 0.98
- **Loading**: Skeleton screens, not spinners
- **Toast Notifications**: Sonner library, bottom-right, 4s duration
- **Map Pins**: Pulse animation for featured properties

### Responsive Breakpoints
- **sm**: 640px (large phones)
- **md**: 768px (tablets)
- **lg**: 1024px (small laptops)
- **xl**: 1280px (desktops)
- **2xl**: 1536px (large screens)

### Accessibility
- WCAG 2.1 AA compliance target
- Color contrast ratio 4.5:1 minimum
- Focus visible states on all interactive elements
- ARIA labels for icon-only buttons
- Keyboard navigation support
- Screen reader tested

### Performance
- Next.js Image component for optimization

## 4. Role-Based Access Control (RBAC)

### User Roles Hierarchy
1. **VISITOR** - Unauthenticated user
2. **USER** - Registered and authenticated
3. **AGENT** - User with agent profile
4. **SERVICE_PROVIDER** - Approved service provider
5. **OWNER** - Property owner (special user type)
6. **TENANT** - Tenant user (special user type)
7. **ADMIN** - Full system access

### Permission Matrix

| Permission | VISITOR | USER | AGENT | PROVIDER | ADMIN |
|-----------|---------|------|-------|----------|-------|
| Browse Public Content | ✓ | ✓ | ✓ | ✓ | ✓ |
| View Map | ✓ | ✓ | ✓ | ✓ | ✓ |
| Submit Contact Form | ✓ | ✓ | ✓ | ✓ | ✓ |
| Register/Login | ✓ | ✓ | ✓ | ✓ | ✓ |
| Post Property | ✗ | ✓ | ✓ | ✗ | ✓ |
| Edit Own Property | ✗ | ✓ | ✓ | ✗ | ✓ |
| Delete Own Property | ✗ | ✓ | ✓ | ✗ | ✓ |
| Post Request | ✗ | ✓ | ✓ | ✓ | ✓ |
| Edit Own Request | ✗ | ✓ | ✓ | ✓ | ✓ |
| Delete Own Request | ✗ | ✓ | ✓ | ✓ | ✓ |
| Create Agent Profile | ✗ | ✓ | ✓ | ✗ | ✓ |
| Link Property-Request | ✗ | ✗ | ✓ | ✗ | ✓ |
| Manage Service Profile | ✗ | ✗ | ✗ | ✓ | ✓ |
| Approve Content | ✗ | ✗ | ✗ | ✗ | ✓ |
| Manage Users | ✗ | ✗ | ✗ | ✗ | ✓ |
| View Admin Dashboard | ✗ | ✗ | ✗ | ✗ | ✓ |
| Export Data | ✗ | ✗ | ✗ | ✗ | ✓ |
| View Payment Logs | ✗ | ✗ | ✗ | ✗ | ✓ |

### Route Guards

#### Public Routes
- `/` - No guard
- `/properties/*` - No guard
- `/requests/*` - No guard (except linking)
- `/agents/*` - No guard
- `/services/*` - No guard
- `/map` - No guard
- `/about`, `/contact`, `/privacy`, `/terms` - No guard

#### Protected Routes (Require Auth)
All `/dashboard/*`, `/agent/*`, `/provider/*`, `/admin/*` routes require authentication.

#### Role Guards
- `/agent/*` - Requires AGENT role
- `/provider/*` - Requires SERVICE_PROVIDER role
- `/admin/*` - Requires ADMIN role

export const hasPermission = (userRole: string, permission: string): boolean => {
  const permissions = ROLE_PERMISSIONS[userRole] || [];
  return permissions.includes(permission);

export const hasAnyPermission = (userRole: string, permissions: string[]): boolean => {
  return permissions.some(p => hasPermission(userRole, p));

  return permissions.every(p => hasPermission(userRole, p));

## 6. Implementation Guidelines

### Middleware/Guard Implementation
1. **Auth Middleware**: Verify JWT token from cookie/headers
2. **Role Guard**: Check user role against route requirements
3. **Permission Guard**: Check specific permission for action
4. **Ownership Guard**: Verify user owns resource for edit/delete

### Frontend Implementation
1. Use `useAuth()` hook to get current user and role
2. Use `<ProtectedRoute>` wrapper for protected pages
3. Use `<PermissionGate>` component for conditional UI rendering
4. Use `<RoleBadge>` component to display user role

### API Integration
1. Send role in JWT payload
2. Backend validates permissions for each protected endpoint
3. Return 403 Forbidden for insufficient permissions
4. Return 401 Unauthorized for missing/invalid auth

### Security Considerations
1. Never trust client-side permission checks alone
2. Always validate on backend for state-changing operations
3. Use HTTPS for all authenticated requests
4. Implement rate limiting on auth endpoints
5. Log permission violations for security audit
