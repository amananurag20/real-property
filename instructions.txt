## Prerequisites Before Starting Any Task

### Environment Requirements
1. **Node.js**: Ensure Node.js is installed (check package.json engines if specified)
2. **Database**: PostgreSQL must be running
3. **Redis**: Required for BullMQ job queues (if using queues)
4. **Environment Variables**: Create `.env` files in both frontend and backend directories

### Backend Environment Variables (Typical)
```
DATABASE_URL="postgresql://user:password@localhost:5432/dbname"
JWT_SECRET="your-secret-key"
REDIS_URL="redis://localhost:6379"
PORT=3000
```

### Frontend Environment Variables (Typical)
```
NEXT_PUBLIC_API_URL="http://localhost:3000"
```

### Setup Steps
1. **Install Dependencies**:
   - Backend: `cd backend && npm install`
   - Frontend: `cd frontend && npm install`

2. **Database Setup**:
   - Run `npm run prisma:migrate:dev` in backend
   - Run `npm run prisma:generate` to generate client

3. **Start Development**:
   - Backend: `npm run start:dev`
   - Frontend: `npm run dev`

### Code Quality Guidelines
- **Linting**: Run `npm run lint` before committing
- **Formatting**: Prettier is configured and enforced via lint-staged
- **Type Safety**: Always use TypeScript; avoid `any` types
- **Commit Conventions**: Follow conventional commits (enforced via commitlint)

### Architecture Patterns
- **Backend**: Follow NestJS modular architecture
- **Database**: Use Prisma migrations for schema changes
- **Frontend**: Use Next.js App Router pattern
- **API**: RESTful endpoints documented via Swagger at `/api/docs`

### Things to Consider
- **Database Schema**: Changes require Prisma migrations
- **Queue Jobs**: Background jobs require Redis to be running
- **WebSockets**: Real-time features need Socket.io setup
- **Authentication**: Protected routes require JWT tokens
- **File Uploads**: Multer is configured for file handling
- **Rate Limiting**: API endpoints have throttling enabled
- **Testing**: Write tests for new features (Jest configured)
